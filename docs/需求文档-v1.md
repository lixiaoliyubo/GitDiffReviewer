# GitDiffReviewer 需求文档（独立桌面工具 · WPF + WebView2）v2

> **交付形态**：**独立 Windows 桌面程序**（不是一个 IDE 插件、也不是 Web 服务）。双击 `GitDiffReviewer.exe` 打开一个窗口，窗口里是 WebView2 承载的本地 Web UI。
> **本文档的用法**：整份发给 AI（豆包），按 §14 的批次顺序实现；每批做完先 `dotnet build` 验收，再让它继续。
> **不要读别的文档**：实现只需要这一份。仓库里若还有旧的 `需求文档-v1.md`（VS Code 扩展版）或 `可行性方案.md`，都已作废，**不要按它们实现**。

---

## 0. 给实现者的硬约束（优先级最高，违反即返工）

1. **独立进程，不依赖任何 IDE**：产物是一个 `GitDiffReviewer.exe`，不装 VS Code、不装 Node、不需要浏览器。禁止出现"VS Code 扩展"相关代码/清单。
2. **只读**：禁止执行任何会修改工作区或仓库的 git 命令。允许的 git 命令只有 §7.2 白名单里的 7 条。
3. **不写入被审阅仓库的任何文件**（含 `.git/`）。所有状态文件写 `%APPDATA%\GitDiffReviewer\`。
4. **不启 HTTP 服务、不监听端口**。Web UI 通过 WebView2 虚拟主机映射（`https://app.local/`）加载。
5. **运行时无网络请求**：Monaco、字体、图标全部本地文件，不引 CDN。
6. 进程调用只允许 `ProcessStartInfo` + `ArgumentList`；禁止 `cmd /c`、禁止拼接命令行字符串。
7. NuGet 包**只允许两个**：`Microsoft.Web.WebView2`、`System.Text.Encoding.CodePages`（GB18030 解码需要）。不许引 UI 框架、不许引 JSON 之外的工具库。
8. 界面文案**中文**，代码注释**中文**。
9. 每完成一个批次必须先 `dotnet build -c Release` 通过（0 error 0 warning），再进入下一批。
10. 输出文件时给**完整内容**，不要用 `...省略...`。
11. 文档没写死的细节，选**最小实现**，并在 `README.md` 的「决策记录」补一行。

## 1. 背景与目标

### 1.1 问题

`git pull` 之后工作区是干净的，**看不到这次到底改了什么文件**。IDE 的源代码管理面板只显示"未提交改动"，对"已经拉进来的改动"是空白。用户只能翻 `git log`、或者去 Gitee/GitHub 网页逐个看。

### 1.2 目标

一个**独立双击即用**的 Windows 工具：

- 记住"上次审阅到哪个 HEAD"（基线），跨重启不丢；
- 一次拉取（或任意时间间隔）后，列出期间所有变更文件（新增/修改/删除/重命名），带增删行数；
- 点某个文件，右侧用 **Monaco diff 编辑器**展示基线与当前的对比，**默认行内（红删绿加）**，可切并排，`F7`/`Shift+F7` 跳转改动；
- 全程不写仓库、不联网、不需要任何 IDE。

### 1.3 一句话验收

> 双击 exe → 选一个 git 仓库 → 拉取后点「刷新」→ 左侧列出 12 个变更文件 → 点一个，右侧出现红绿行内 diff → 点「标记已审阅」，左侧清空。

| 场景 | 用户动作 | 期望 |

### 4.2 职责边界（不要越界）

| 层 | 负责 | **不负责** |
|---|---|---|
| C#（WPF 侧） | 所有 git 调用、编码、基线、持久化、窗口、文件监听 | 不生成 HTML、不做 diff 计算 |
| JS（WebView2 侧） | 渲染列表/工具栏、Monaco diff、键盘交互 | 不直接调 git、不读文件系统 |

> JS 侧拿到的永远是"已经算好并解码好的数据"，它不应该知道 git 的存在。

### 4.3 为什么不用本地 HTTP 服务

不用 `HttpListener`/Kestrel 起 127.0.0.1 端口，理由：① 少一个可被其它进程/网页访问的攻击面；② 不用处理端口冲突；③ WebView2 官方支持虚拟主机映射，`https://app.local/` 自带正确 MIME 与同源策略。

### 4.4 WebView2 初始化（关键代码形状）

```csharp
var userDataFolder = Path.Combine(appDataDir, "WebView2");
var env = await CoreWebView2Environment.CreateAsync(null, userDataFolder);
await WebView.EnsureCoreWebView2Async(env);

WebView.CoreWebView2.SetVirtualHostNameToFolderMapping(
    "app.local",
    Path.Combine(AppContext.BaseDirectory, "wwwroot"),
    CoreWebView2HostResourceAccessKind.DenyCors);

WebView.CoreWebView2.WebMessageReceived += OnWebMessage;
WebView.CoreWebView2.Navigate("https://app.local/index.html");
```

**要求**：
- `userDataFolder` 必须在 `%APPDATA%` 下（不要在仓库里、不要在当前目录）。
- 若 `CoreWebView2Environment.CreateAsync` 抛异常（未安装 WebView2 Runtime）→ 弹窗提示中文说明 + 打开官方下载页的按钮，然后退出（不要静默崩溃）。

## 5. 功能需求

### FR-1 启动与仓库

**启动流程**：
1. 单实例检查：命名 Mutex `Global\\GitDiffReviewer`；已有实例则激活它并退出。
2. 读 `settings.json`；若 `repos` 为空 → 显示「选择仓库」空态页，按钮打开文件夹选择框（`Microsoft.Win32.OpenFolderDialog`，.NET 8 WPF 自带）。
3. 校验所选目录：执行 `rev-parse --git-dir`，失败提示「这不是 git 仓库」。
4. 记住最近使用的仓库（`settings.json.activeRepo`），下次启动直接打开。

**顶部仓库下拉**：`settings.json.repos` 列表 + 「添加仓库…」+「移除」。

**验收 AC-1**：删掉 `%APPDATA%\GitDiffReviewer` 后启动，出现"选择仓库"空态，能完成一次添加并记住。

---

### FR-2 基线（核心，照抄实现）

每个仓库存两个值（`state\<repoKey>.json`）：

| 字段 | 含义 | 何时写 |
|---|---|---|
| `baselineHead` | 用户上次审阅到的 40 位 SHA | ①首次初始化 ②点「标记已审阅」③手选提交 |
| `lastSeenHead` | 工具上次看到的 HEAD | 每次检测到 HEAD 变化 |
| `baselineAt` | 记录时间（ISO 8601） | 同上 |
| `baselineSource` | `initial` / `manual` / `picked` | 同上 |

**规则（不得改变）**：

1. 某仓库没有 `baselineHead` → 设为**当前 HEAD**，状态栏提示「已记录当前为基线（3 秒）」。
2. **HEAD 变化时绝不自动推进 `baselineHead`**，只更新 `lastSeenHead`，然后重算。
3. 只有用户显式操作才推进：「标记已审阅」或「选择基线提交…」。
4. 基线 commit 不存在（被 gc）→ 提示「基线已失效，已重置为当前 HEAD」并重置。
5. 基线不是 HEAD 祖先 → 照常计算，`nonFastForward = true`，列表顶部显示警告条。

> ⚠️ 第 2 条是产品底线：自动推进会让"拉了但没看"的改动永久丢失。

**验收 AC-2**：标记基线 → 外部终端 pull → 工具显示 N → **关闭再打开**工具，N 不变 → 点标记 → 归零。

---

### FR-3 变更集

**输入**：`baselineHead`（base）、`HEAD`（target）。

**步骤**：
1. `merge-base --is-ancestor <base> <target>` → 退出码 0 祖先 / 1 非祖先 / 其它错误。
2. `diff --name-status -z --find-renames=50%` → 状态 + 路径。
3. `diff --numstat -z --find-renames=50%` → 增删行数。
4. 合并排序：状态优先级 `M → A → D → R → C → 其它`，同状态按路径升序。
5. 超过 `maxFiles`（默认 3000）截断，`truncated = true`。

**边界**：二进制（numstat 为 `-`/`-`）→ `binary=true`；重命名取到旧+新路径；空变更集正常返回空数组。

**验收 AC-3**：fixture 仓库（§15）返回恰好 7 条，状态/行数与 `git diff --name-status`、`--numstat` 一致。

### FR-4 左侧变更列表

**结构**：
```
[警告条]（仅非快进时）
[统计]  12 个文件 · +248 / −97 · 新增3 修改8 删除0 重命名1
[分组]  修改 (8)  ▾
          RouterVo.cs            src/Yuandl.Model/…   +12 −3
        新增 (3)  ▾ …
        删除 (1)  ▾ …
        重命名 (1) ▾ …
```

- 每行：状态色块（A 绿 / M 黄 / D 红 / R 蓝）+ 文件名 + 相对路径 + `+X −Y`（二进制显示"二进制"）。
- 点击行 → 右侧打开该文件 diff；当前行高亮。
- 顶部有搜索框（按路径过滤）和状态筛选（全部 / 只看新增 / 只看修改 / 只看删除）。
- 空态：「没有待审阅的改动」+ 按钮「刷新」「标记当前为基线」。
- 列表超过 500 项时用虚拟滚动（只渲染视口内）。

**验收 AC-4**：fixture 7 条正确分组；2000 条时滚动不卡（< 16ms/帧）。

### FR-5 右侧 Monaco diff

**布局**：左侧列表 320px 可拖拽，右侧占满剩余。

**加载**：
1. 用户点文件 → JS 发 `getFileContent { path, oldPath, status }`。
2. C# 返回 `{ oldText, newText, oldLabel, newLabel, encoding, binary, truncated, language }`。
3. JS 用 `monaco.editor.createDiffEditor` 渲染。

**Monaco 配置（必须）**：
```js
const editor = monaco.editor.createDiffEditor(el, {
  renderSideBySide: false,          // 默认行内 —— 这就是"截图里的效果"
  readOnly: true,
  automaticLayout: true,
  renderOverviewRuler: true,        // 右侧改动色条
  hideUnchangedRegions: { enabled: true, contextLineCount: 3, minimumLineCount: 5 },
  diffWordWrap: 'off',
  ignoreTrimWhitespace: false,
  originalEditable: false
});
editor.setModel({
  original: monaco.editor.createModel(oldText, language, monaco.Uri.parse('inmemory://old/' + name)),
  modified: monaco.editor.createModel(newText, language, monaco.Uri.parse('inmemory://new/' + name))
});
```
- 语言由扩展名映射（`.cs→csharp`, `.ts→typescript`, `.vue→html`, `.json→json`, `.md→markdown`, 其它 `plaintext`）。
- 切换并排/行内：`editor.updateOptions({ renderSideBySide: !sideBySide })`，并持久化到 `settings.json.inlineDiff`。
- **跳转改动**：`F7` → `editor.trigger('keyboard', 'editor.action.diffReview.next', null)`；`Shift+F7` → `...previous`。用 `editor.addCommand(monaco.KeyCode.F7, ...)` 注册（standalone 版默认没有这两个键位）。
- 复制：允许 `Ctrl+C`（readOnly 编辑器默认可用），不需要额外实现。
- **大文件**：单侧文本 > 2MB 或 > 20000 行 → 只传前 20000 行，`truncated=true`，顶部显示黄条「文件过大，已截断，仅显示前 20000 行」。
- **二进制**：`binary=true` → 不建编辑器，显示占位：「二进制文件已变更（无法文本对比）」，若扩展名是图片（png/jpg/gif/webp/svg）则两侧显示 `<img>` 预览（内容走 base64）。
- 切换文件时先 `dispose()` 旧 model 与 editor 实例（或复用 editor 只换 model，必须 dispose 旧 model）。

**验收 AC-5**：M/A/D/R 四类都能正确打开；GBK 中文不乱码；二进制有占位；`F7` 能在改动间跳。

### FR-7 自动检测 HEAD 变化

1. `FileSystemWatcher` 监听 `<repo>\.git\HEAD` 与 `<repo>\.git\refs\heads\`（`IncludeSubdirectories=true`），事件后 **debounce 800ms**。
2. 兜底轮询：每 30 秒执行一次 `rev-parse HEAD`（FileSystemWatcher 在某些网络盘/权限下不可靠）。
3. HEAD 变化 → 更新 `lastSeenHead`、重算、推消息 `headChanged` 给前端 → 前端刷新列表 + 弹一条**非模态**提示「检测到 N 个文件变更」（3 秒自动消失，可配置关闭）。
4. 切换仓库时重建 watcher。

**验收 AC-7**：外部终端 `git pull` 后 2 秒内，列表与统计自动更新。

### FR-8 标记已审阅

`baselineHead = 当前 HEAD`，`baselineAt = now`，`baselineSource = manual` → 重算（空集）→ 前端清空列表并提示「已把 abc1234 记为基线」。

**验收 AC-8**：点击后列表清空、统计归零、持久化生效（重启后仍为空）。

---

### FR-9 选择基线

「选择基线…」→ C# 执行 `log -n 30 --format=%H%x09%h%x09%s` → 返回列表 → 前端弹下拉（列表项显示 `短SHA 提交说明`）→ 选中后：
1. 先用 `rev-parse --verify --end-of-options <rev>^{commit}` 校验成 40 位 SHA；
2. 写入 `baselineHead`，`baselineSource = picked`；
3. 重算。

**验收 AC-9**：选一个三天前的提交，列表显示这三天所有改动。

## 6. 数据结构

### 6.1 C#（`Models/`）

```csharp
public enum ChangeStatus { Added, Modified, Deleted, Renamed, Copied, TypeChanged, Broken, Unknown }

public sealed record ChangeEntry(
    string Path,               // 新路径，相对仓库根，正斜杠
    string? OldPath,           // 重命名/复制的旧路径
    ChangeStatus Status,
    string? Score,             // 重命名相似度 "100"
    int Insertions,
    int Deletions,
    bool Binary);

public sealed record ChangeSet(
    string RepoRoot,
    string BaseSha, string TargetSha,
    string BaseShort, string TargetShort,
    bool NonFastForward,
    bool Truncated,
    IReadOnlyList<ChangeEntry> Entries,
    int TotalInsertions, int TotalDeletions);

public sealed record BaselineRecord(string Head, string RecordedAt, string Source);
```

### 6.2 前后端消息（JSON，字段名 camelCase）

| type（JS→C#） | payload | reply 的 data |
|---|---|---|
| `bootstrap` | `{}` | `{ repos, activeRepo, settings, hasWebView2:true }` |
| `addRepo` | `{}`（C# 自己弹目录框） | `{ repo }` |
| `selectRepo` | `{ path }` | `{ repo }` |
| `listChanges` | `{ force?: boolean }` | `ChangeSet` + `{ baseline }` |
| `getFileContent` | `{ path, oldPath?, status }` | `{ oldText, newText, oldLabel, newLabel, encoding, binary, truncated, language, oldImage?, newImage? }` |
| `markReviewed` | `{}` | `{ baseline }` |
| `chooseBaseline` | `{}` | `{ commits: [{sha, short, subject}] }` |
| `setBaseline` | `{ sha }` | `{ baseline }` |
| `saveSettings` | `{ inlineDiff?, notifyOnChange? }` | `{ settings }` |

**统一 envelope**：

```json
// JS → C#
{ "id": "r-17", "type": "listChanges", "payload": {} }
```

## 7. 实现规范

### 7.1 GitRunner（唯一进程出口）

```csharp
public sealed record GitResult(int ExitCode, byte[] StdOut, string StdErr);

public sealed class GitRunner(string repoRoot)
{
    private static readonly string[] Prefix = ["--no-pager", "-c", "core.quotepath=false"];

    public async Task<GitResult> RunAsync(IReadOnlyList<string> args, int timeoutMs = 30_000,
                                          int maxBytes = 32 << 20, CancellationToken ct = default)
    {
        var psi = new ProcessStartInfo("git")
        {
            WorkingDirectory = repoRoot,
            RedirectStandardOutput = true,
            RedirectStandardError = true,
            UseShellExecute = false,
            CreateNoWindow = true
            // 不要设置 StandardOutputEncoding：要拿原始字节
        };
        foreach (var a in Prefix) psi.ArgumentList.Add(a);
        foreach (var a in args) psi.ArgumentList.Add(a);
        psi.Environment["GIT_TERMINAL_PROMPT"] = "0";
        psi.Environment["GIT_OPTIONAL_LOCKS"]  = "0";
        psi.Environment["GIT_PAGER"]           = "cat";
        psi.Environment["LC_ALL"]              = "C.UTF-8";

        using var p = Process.Start(psi) ?? throw new GitException("GIT_NOT_FOUND", "未找到 git，请安装 Git for Windows");
        using var ms = new MemoryStream();
        var readTask = ReadLimitedAsync(p.StandardOutput.BaseStream, ms, maxBytes, ct);
        var errTask  = p.StandardError.ReadToEndAsync(ct);
        using var cts = CancellationTokenSource.CreateLinkedTokenSource(ct);
        cts.CancelAfter(timeoutMs);

        try { await Task.WhenAll(readTask, errTask).WaitAsync(cts.Token); }
        catch (OperationCanceledException) when (!ct.IsCancellationRequested)
        {
            try { p.Kill(entireProcessTree: true); } catch { }
            throw new GitException("GIT_TIMEOUT", $"git 执行超时（{timeoutMs}ms）");
        }
        await p.WaitForExitAsync(ct);
        return new GitResult(p.ExitCode, ms.ToArray(), await errTask);
    }

    // ReadLimitedAsync：带计数拷贝，超过 maxBytes 就停止读取并返回 truncated 标记（不要 MemoryStream 无上限）
}
```

**要求**：
- 所有 git 调用都走这一个方法。
- 返回原始字节，解码在 §7.4 按字段做。
- 输出上限必须生效（§11 要求内存 < 200MB）。
- 失败要带 `stderr`，错误文案要给用户看懂的中文。

### 7.2 git 命令白名单（只有这 7 条）

| 用途 | 参数（Prefix 之外） |
|---|---|
| 当前 HEAD | `rev-parse HEAD` |
| 校验提交 | `rev-parse --verify --end-of-options <rev>^{commit}` |
| 祖先判断 | `merge-base --is-ancestor <a> <b>`（只看退出码） |
| 变更清单 | `diff --no-ext-diff --no-textconv --find-renames=50% --name-status -z <a> <b>` |
| 增删行数 | `diff --no-ext-diff --no-textconv --find-renames=50% --numstat -z <a> <b>` |
| 取文件内容 | `show <40位sha>:<path>` |
| 最近提交 | `log -n 30 --format=%H%x09%h%x09%s <HEAD>` |

> `--end-of-options` 需要 git ≥ 2.24。若报 unknown option，可去掉，但**必须**先用正则 `/^[0-9a-fA-F]{7,64}$/` 校验输入，且把 `rev-parse` 的结果（40 位 hex）作为后续所有命令的参数。

### 7.3 `-z` 解析（必须按字节切）

```csharp
static List<byte[]> SplitNul(byte[] buf)
{
    var list = new List<byte[]>();
    int start = 0;
    for (int i = 0; i < buf.Length; i++)
        if (buf[i] == 0) { list.Add(buf[start..i]); start = i + 1; }
    if (start < buf.Length) list.Add(buf[start..]);
    return list;
}

// name-status：元素序列 = 状态、路径（R/C 为 状态、旧路径、新路径）
// numstat：每个元素形如 "12\t3\tpath"；rename 时第三段为空，随后两个元素是旧路径、新路径
```

**禁止**：对整段 `byte[]` 先 `Encoding.UTF8.GetString` 再按 `\0` 拆 —— 那会把 GBK 路径解坏。必须先按 `0x00` 切字节，再逐个解码。

### 7.4 编码

```csharp
static string Decode(byte[] bytes)
{
    try { return new UTF8Encoding(false, throwOnInvalidBytes: true).GetString(bytes); }
    catch (DecoderFallbackException)
    {
        Encoding.RegisterProvider(CodePagesEncodingProvider.Instance);
        return Encoding.GetEncoding("GB18030").GetString(bytes);
    }
}
```

- 顺序不能反：严格 UTF-8 失败才回退 GB18030。
- 传给 Monaco 的文本统一 UTF-8（`json` 序列化天然是 UTF-8）。
- 图片预览：原始字节 → `data:image/png;base64,...`。

### 7.5 基线状态机

```
启动 → 加载 state\<repoKey>.json
  ├─ 无 baselineHead → 写 = HEAD（source=initial）→ 变更集为空 → 提示"已记录当前为基线"
  └─ 有 → 计算 baselineHead..HEAD → 返回 entries

HeadWatcher 触发 → lastSeenHead = 新 HEAD → 不碰 baselineHead → 重算 → 推送 headChanged

用户「标记已审阅」 → baselineHead = HEAD（manual）→ 重算（空）
用户「选择基线」   → 校验 SHA → baselineHead = sha（picked）→ 重算
```

### 7.6 状态文件

```
%APPDATA%\GitDiffReviewer\
├─ settings.json          { repos:[{path,name,addedAt}], activeRepo, inlineDiff:true, notifyOnChange:true,
│                           maxFiles:3000, onboardingDone:false, window:{x,y,w,h} }
├─ state\<repoKey>.json   { baselineHead, lastSeenHead, baselineAt, baselineSource }
├─ logs\app-YYYYMMDD.log
└─ WebView2\              （WebView2 用户数据，必须在 APPDATA 下，不在仓库里）
```

`repoKey` = `SHA256(规范化绝对路径)` 取前 16 位 hex（`Path.GetFullPath` + 全小写）。

**要求**：写文件用"临时文件 + `File.Move(overwrite:true)`"原子替换，避免半截 JSON。

### 7.7 路径安全

1. 传给 `show` 的 path **必须**来自本次变更集（`Dictionary<string, ChangeEntry>` 查表，查不到抛错）。
2. 拼绝对路径后校验：
   ```csharp
   var full = Path.GetFullPath(entry.Path, repoRoot);          // 注意参数顺序：path 在前、basePath 在后
   var rel  = Path.GetRelativePath(repoRoot, full);
   if (rel.StartsWith("..") || Path.IsPathRooted(rel)) throw new GitException("PATH_ESCAPE", "路径越界");
   ```
3. rev 参数必须先是 40 位 hex。
4. 前端传来的 `path` 一律不信任，按 1、2 校验。

### 7.8 WebView2 与消息

- 前端资源：`wwwroot/`（`index.html`、`app.js`、`style.css`、`vendor/monaco/vs/...`）。
- 虚拟主机：`app.local`，`CoreWebView2HostResourceAccessKind.DenyCors`。
- 禁用不需要的能力：`CoreWebView2Settings.AreDevToolsEnabled=true`（开发期保留）、`AreDefaultContextMenusEnabled=false`、`IsStatusBarEnabled=false`、`AreBrowserAcceleratorKeysEnabled=true`（要保留 F7 等）。
- 消息：`WebMessageReceived` 里 `e.WebMessageAsJson` → 反序列化 → 按 `type` 分发 → `CoreWebView2.PostWebMessageAsJson(json)` 回包。**所有异常都要转成 `ok:false` 回包，不允许抛到 UI 线程崩掉**。
- JSON 序列化：`System.Text.Json`，`PropertyNamingPolicy = JsonNamingPolicy.CamelCase`。
